3. The z-index / Stacking Context Trap

Box A (context z-index: 1)
Child z-index: 9999
Box B (context z-index: 2)

Notice: Box B visually covers Box A's red child, even though the child's own z-index: 9999 is far higher than Box B's z-index: 2. That's because the red child is trapped inside Box A's stacking context, and Box A's context (z-index 1) already loses to Box B's context (z-index 2) — the child can never "escape" its parent's context to compete directly with Box B.
